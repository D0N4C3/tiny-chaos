# Agent operating rules and environment protocol

1. Detect available engine, Android SDK/JDK and MCP tools via supported discovery; do not assume Blender/Illustrator MCP names or schemas. If available, invoke tools with their actual documented signatures.
2. Each asset generated by external tools must have a source project, preview, exported runtime file, import QA and provenance entry. Do not claim an asset is ready until it is visible in Godot on an Android build.
3. If tools are unavailable, write a standalone Blender Python script or procedural SVG source **in the development repository** and document how to run it. Preserve editable originals.
4. Pin third-party plugin versions and dependency checksums. Do not blindly download and run executable code from asset sites; use publishers' pages and verified releases.
5. Build on-device early and repeatedly. Working editor play mode does not prove Android export, billing or ads are functional.
6. Keep all secrets/signing keystores outside version control. Test ad IDs must never be replaced with invented production IDs.
7. All content can be regenerated from version-controlled level data; all user progress has backwards-compatible versioned migrations.
8. Every change should have tests, evidence and a tracker status. Include human review tasks explicitly.
9. If a design element hurts accessibility, retention or fairness, document the issue and propose a concrete change rather than silently adding pressure mechanics.

10. Use `AGENTS.md` as the single source of truth within each owned source folder. `CLAUDE.md` must contain only `@AGENTS.md` so Claude and Codex share the same rules without drift.
11. Never eager-import product/tech/art specs into root agent files. Route by task to one or two relevant docs; read more only when needed to resolve the implementation.
12. Initialize Git on the developer's local machine before feature work. After the targeted tests pass, commit each feature (including tracker and accompanying tests) separately. Do not amend, force push or rewrite existing history without explicit authorization.
13. Do not make a Git remote connection automatically. If Git author identity isn't configured, ask the owner to configure it; never invent the owner name or email.
